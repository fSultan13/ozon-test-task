# Нагрузочный тест на Locust

Python 3.11+ и Locust (версия закреплена в `requirements.txt`). Код, виртуальное окружение и отчёты находятся в этой
папке. Нагрузка запускается через библиотечный API Locust без веб-интерфейса. Сервис запускается
отдельно. [Последний отчёт](reports/latest.md), история — в `reports/`.

Установка из корня репозитория:

```sh
python3 -m venv tools/loadtest/.venv
tools/loadtest/.venv/bin/python -m pip install -r tools/loadtest/requirements.txt
```

Окружение `.venv` исключено из Git. В отдельном терминале запустите сервис:

```sh
PUBLIC_BASE_URL=http://localhost:8080 go run ./cmd/api -storage=memory
```

Затем:

```sh
tools/loadtest/.venv/bin/python tools/loadtest/run.py --base-url http://localhost:8080 --label local-memory
tools/loadtest/.venv/bin/python tools/loadtest/run.py --base-url https://short.example/api --label hosted-postgres
tools/loadtest/.venv/bin/python tools/loadtest/run.py --help
```

HTTPS проверяет сертификаты через стандартный CA bundle requests; отключения проверки нет. Прокси из переменных
окружения не используются: запросы идут прямо на заданный стенд. Префикс пути сохраняется во всех запросах. Адрес
публичных ссылок может отличаться от адреса стенда:
утилита извлекает код, но обращается только к заданному `--base-url`. Редиректы не выполняются.

| Параметр         | По умолчанию | Назначение                                          |
|------------------|--------------|-----------------------------------------------------|
| `--base-url`     | обязательный | HTTP(S)-адрес API без credentials, query и fragment |
| `--duration`     | 30           | Длительность выдачи нагрузки, секунды               |
| `--concurrency`  | 10           | Фиксированное число пользователей Locust            |
| `--timeout`      | 3            | Таймаут блокирующей операции сокета, секунды        |
| `--dataset-size` | 100          | Количество подготавливаемых связей                  |
| `--max-requests` | 100000       | Общий предел запросов измеряемой фазы               |
| `--label`        | unspecified  | Описание окружения, например `local-memory`         |

Подготовка последовательно сокращает и читает детерминированные адреса: по умолчанию создаёт до 100 записей (при
изменении `--dataset-size` — до указанного числа). Повторные запуски переиспользуют их. Удаления нет. Подготовка
исключена из метрик и останавливается на первой ошибке.

Измеряемая фаза не создаёт новых адресов: каждый 20-й запрос — повторный POST, остальные — GET. Каждый полный цикл из
100 запросов содержит 95 GET и 5 POST; для неполного цикла пропорция может отличаться. Каждый пользователь Locust
переиспользует свою HTTP-сессию и отправляет следующий запрос только после ответа. Пользователи выполняются конкурентно
через gevent, без отдельных потоков ОС. Паузы между запросами нет; измерение начинается после создания всех
пользователей. Это закрытая модель нагрузки без заданного целевого RPS. Число сохранённых измерений ограничено
`--max-requests`, размер одного ответа — 64 KiB. После длительности/лимита новые запросы не выдаются; запросы в полёте
завершаются. Таймаут действует на отдельные операции I/O, а не на весь запрос: медленная передача частями может длиться
дольше. Общая длительность запуска также включает подготовку.

Успех запроса — HTTP 200, JSON с ожидаемым исходным адресом для GET или прежним кодом для POST. Ошибки продолжают
учитываться до конца измерения. Код выхода: `0` — без ошибок, `1` — ошибка теста, подготовки или записи отчёта, `2` —
неверные аргументы, `130` — Ctrl+C. При Ctrl+C прекращается выдача запросов, ожидаются текущие операции и сохраняется
частичный отчёт.

Каждый запуск после валидации аргументов сохраняет отдельный Markdown-файл с UTC-временем и уникальным суффиксом. После
записи истории атомарно обновляется `reports/latest.md`; ошибки теста также обновляют последний отчёт. Ошибки записи
файла могут помешать сохранению. Содержимое ответов и созданные ссылки в отчёт не попадают.

Отчёт содержит параметры, причину остановки, фактическую длительность, общий/успешный RPS, количество и долю ошибок,
задержки отдельно для успешных и ошибочных GET/POST. Задержка включает чтение и проверку ответа; перцентили вычисляются
nearest-rank. RPS использует полное время измерения, включая завершение запросов в полёте. Любая ошибка означает FAIL;
порогов задержки и RPS нет. Измеряется стенд вместе с сетью и Locust-клиентом:
результат не определяет максимальную производительность сервиса или число пользователей.

Тесты самой утилиты:

```sh
tools/loadtest/.venv/bin/python -m unittest discover -s tools/loadtest -v
```

Подход запуска: [Using Locust as a library](https://docs.locust.io/en/stable/use-as-lib.html).
