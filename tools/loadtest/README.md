# Нагрузочные тесты Locust

Нужен Python 3.11+. Сервис запускается отдельно.

```sh
python3 -m venv tools/loadtest/.venv
tools/loadtest/.venv/bin/python -m pip install -r tools/loadtest/requirements.txt
tools/loadtest/.venv/bin/python tools/loadtest/run.py --base-url http://localhost:8080 --label local-memory
```

## Одиночный запуск

| Параметр | По умолчанию |
|---|---|
| `--base-url` | обязательный HTTP(S)-адрес без credentials, query и fragment |
| `--duration` | 30 с |
| `--concurrency` | 10 клиентов |
| `--timeout` | 3 с на I/O-операцию, не весь запрос |
| `--dataset-size` | 100 ссылок |
| `--max-requests` | 100 000 |
| `--label` | unspecified |

Подготовка создаёт или переиспользует ссылки, проверяет GET и не входит в метрики.
Нагрузка: 95% GET / 5% повторных POST, без пауз и создания новых URL.
Каждый клиент переиспользует HTTP-сессию и ждёт ответа перед следующим запросом.
Успех — HTTP 200 и ожидаемый URL/код в JSON; любая ошибка даёт FAIL.

HTTPS проверяет сертификаты; редиректы и прокси окружения отключены.
Запросы идут только на `--base-url`, его префикс пути сохраняется. Ответ ограничен 64 KiB.
После срока/лимита завершаются запросы в полёте. RPS учитывает это время;
задержки включают чтение и проверку ответа, перцентили — nearest-rank.

Отчёты: отдельный `.md` в `reports/` и [latest.md](reports/latest.md).
Коды выхода: `0` — PASS, `1` — ошибка теста/записи, `2` — аргументы, `130` — Ctrl+C с частичным отчётом.

## Ступенчатый и длительный профиль VPS

```sh
tools/loadtest/.venv/bin/python tools/loadtest/suite.py \
  --memory-url http://168.113.172.116:18080 \
  --postgres-url http://168.113.172.116:18081 \
  --output-dir tools/loadtest/reports/NEW-RUN
```

Сначала Memory, затем PostgreSQL: 10 → 25 → 50 → 100 клиентов по 120 с,
затем 50 клиентов на 600 с. Между этапами — 10 с паузы. Набор — 100 ссылок, I/O timeout — 3 с,
лимит — 2 млн запросов на этап. Достижение лимита раньше срока не проверяет полную длительность.

В каждом окне ~10 с (включая последнее неполное) ≥1% ошибок или p95 ≥1 с останавливают этап.
Любой FAIL отменяет остальные этапы стенда. Ctrl+C сохраняет частичный этап, остальные — SKIP.
Каталог результатов должен быть новым: `summary.md`, отчёты этапов и `results.json`
с окнами, ошибками, CPU-временем клиента и пиковым RSS процесса. `latest.md` не обновляется.

[Результаты от 8 ноября 2026 года](reports/2026-11-08-vps-step-endurance/summary.md).
Измеряется сервис вместе с сетью, gateway и клиентом. Прогрева и серверных метрик нет;
создание новых URL, заполнение хранилища и рестарты не проверяются. Это не оценка предельного RPS.
